## 文件名不是转换器

Clash/mihomo 常用 YAML 配置，sing-box 有自己的 JSON 配置结构。将 .yaml 改成 .json 不会完成转换；即使解析成功，也不代表字段或协议相容。可乐云资料站不保证服务同时提供两种格式，先核实你已有账户的输出选项。

## 把迁移拆成三份内容

节点连接参数、规则意图和本机接管设置应分别整理。节点部分包含协议、地址及认证，需要保持私密；规则部分说明哪些目标走哪个出口；本机设置还与操作系统和客户端权限相关，不能从旧机器原样复制。

| 项目 | 迁移前要回答 |
| --- | --- |
| 节点协议 | 新内核是否支持相同协议与选项 |
| 分流意图 | 新规则怎样表达同一需求 |
| DNS | 解析是否经预期路径 |
| TUN 或系统代理 | 新设备是否需要同一接管方式 |

## 优先取得原生格式

如果服务明确提供新客户端格式，优先用它建立最小可用连接。没有原生格式时，按新内核官方文档逐项核对，不把私人配置交给公共转换器。本文不提供自动转换保证，复杂传输、TLS 或规则集差异需要具体检查。

## 一次迁移一个用途

先在新客户端导入最小配置，完成普通公开网页访问，再逐项加入你的个人规则。mihomo 的规则集不能直接当 sing-box 的规则集使用；语法、类型与版本要求都要核对。每加一项检查最终配置与连接结果。

原客户端保留但不要同时接管网络。新配置稳定后再按你的账户规则处理旧设备，旧配置备份仍应加密保存。基础步骤见[导入订阅](/tutorials/import-subscription/)。
