## 报错是获取还是解析

规则集更新失败可能发生在 HTTP 下载，也可能发生在解析内容。先记录规则集名称、错误类型与客户端内核版本。不要因网络错误改规则内容，也不要因格式不兼容换节点反复下载。

## 同一个链接不代表同一种内容

mihomo 规则集合有不同 behavior 与 format；domain、ipcidr、classical 描述内容行为，yaml、text、mrs 描述格式。sing-box 使用另一套规则集结构。文件后缀和压缩包名称只能辅助识别，必须对照原始发布说明。

| 要核对 | 示例问题 |
| --- | --- |
| 来源 | 是否为维护者发布的正确资源 |
| 格式 | YAML、文本或二进制是否匹配 |
| 行为类型 | 内容是域名、网段还是经典规则 |
| 引用 | 规则是否引用了存在的集合名 |
| 版本 | 当前内核是否支持该格式 |

## 先保留旧规则的意图

迁移前记录规则为什么存在，如“家庭内网直连”或“某应用使用指定组”。新格式不支持原有语法时，重建对应意图，不能简单删除规则让默认出口替代它。也不把陌生规则全集并入个人配置而不审查来源。

## 用最小集合验证

先用维护者提供、与你版本匹配的最小示例核对能否加载，再确认一条连接命中预期规则。示例本身不是服务政策，不能用规则名称宣称流媒体解锁。若更新后故障，恢复之前可用版本并记录差异。

不要打开客户端安全路径限制，只为把规则写到任意系统目录。缓存路径按客户端说明选择，保证不同集合不互相覆盖。

相关迁移步骤见[Clash 与 sing-box 格式迁移](/tutorials/clash-singbox-format-migration/)。
